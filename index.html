Project Overview

Music streaming platforms manage millions of songs, artists, albums, playlists, and user interactions every day. To support these operations efficiently, a well-structured database design is essential. This project designs and implements a relational database for a Music Streaming Playlist Platform using MySQL, managing users, artists, albums, songs, playlists, and playlist-song relationships while maintaining data integrity through primary and foreign key constraints.

Query Result
JOIN 3 Tables
Artist → Album → Song
6 ROWS • SUCCESS 
SELECT artist.name, album.title, song.title, song.duration
FROM artist
JOIN album ON artist.artist_id = album.artist_id
JOIN song ON album.album_id = song.album_id;
Why This Query Matters
Proves 3-table JOIN works correctly. This is the core pattern for any music app: show song with its artist and album in one list.

Database Schema

6 tables, normalized to 3NF.

TableDescription
userStores user information
artistStores artist information
albumStores album information
songStores song information
playlistStores playlist information
playlist_songJunction table — Playlist ↔ Song
Key Design: playlist_song solves Many-to-Many. One Playlist can contain many Songs, one Song can appear in many Playlists.

System Features

What the database supports.

User Management: Store user info, manage playlist ownership
Artist Management: Store artist info, track songs & albums
Album Management: Manage albums, associate with artists
Song Management: Store song info, track duration
Playlist Management: Create public / private playlists
Playlist-Song: Many-to-Many via junction table
